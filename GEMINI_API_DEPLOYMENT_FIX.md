# Gemini API Deployment Fix

## Problem

The Gemini API (`https://generativelanguage.googleapis.com/v1beta/models/gemini-flash-latest:generateContent`) is not working after deployment because the `GEMINI_API_KEY` environment variable is not being passed to the frontend container.

## Root Cause

1. The `docker-entrypoint.sh` script only generates `config.js` with `API_BASE_URL`
2. The `GEMINI_API_KEY` is not included in the runtime configuration
3. The `docker-compose.prod.yml` doesn't include `GEMINI_API_KEY` in the frontend environment variables

## Solution

### Step 1: Update docker-entrypoint.sh

Update `apps/frontend/docker-entrypoint.sh` to include `GEMINI_API_KEY`:

```bash
#!/bin/sh
set -e

# Default API base URL (can be overridden via environment variable)
API_BASE_URL="${API_BASE_URL:-http://localhost:3000/api/v1}"
GEMINI_API_KEY="${GEMINI_API_KEY:-}"

# Validate API_BASE_URL is set
if [ -z "$API_BASE_URL" ]; then
  echo "❌ ERROR: API_BASE_URL environment variable is not set!"
  echo "   Set it in your .env file or docker-compose.yml"
  exit 1
fi

echo "🔧 Generating config.js with API_BASE_URL=${API_BASE_URL}"
if [ -n "$GEMINI_API_KEY" ]; then
  echo "🔧 GEMINI_API_KEY is set (length: ${#GEMINI_API_KEY} characters)"
else
  echo "⚠️  WARNING: GEMINI_API_KEY is not set - Gemini AI features will not work"
fi

# Generate config.js file with runtime configuration
# Escape single quotes in values to prevent script injection
ESCAPED_URL=$(echo "$API_BASE_URL" | sed "s/'/\\\'/g")
ESCAPED_GEMINI_KEY=$(echo "$GEMINI_API_KEY" | sed "s/'/\\\'/g")
cat > /usr/share/nginx/html/config.js <<EOF
// Runtime configuration injected at container startup
// This file is generated by docker-entrypoint.sh
// DO NOT EDIT MANUALLY - it will be regenerated on container restart
window.__APP_CONFIG__ = {
  API_BASE_URL: '${ESCAPED_URL}',
  GEMINI_API_KEY: '${ESCAPED_GEMINI_KEY}'
};
EOF

# Set proper permissions
chown nginx:nginx /usr/share/nginx/html/config.js
chmod 644 /usr/share/nginx/html/config.js

# Verify the file was created and has content
if [ -f /usr/share/nginx/html/config.js ]; then
    echo "✅ config.js created successfully"
    echo "📄 config.js contents (API_BASE_URL only, key hidden):"
    sed 's/GEMINI_API_KEY:.*/GEMINI_API_KEY: "***HIDDEN***"/' /usr/share/nginx/html/config.js
else
    echo "❌ ERROR: config.js was not created!"
    exit 1
fi

# Execute the main command (nginx)
exec "$@"
```

### Step 2: Update docker-compose.prod.yml

Add `GEMINI_API_KEY` to the frontend service environment:

```yaml
  frontend:
    image: hsense/facility-erp-frontend:latest
    container_name: facility-erp-frontend-prod
    platform: linux/amd64
    environment:
      API_BASE_URL: ${API_BASE_URL:-http://backend:3000/api/v1}
      GEMINI_API_KEY: ${GEMINI_API_KEY:-}  # Add this line
    ports:
      - "${FRONTEND_PORT:-80}:80"
    # ... rest of configuration
```

### Step 3: Update app_config.dart

Ensure `app_config.dart` reads `GEMINI_API_KEY` from `window.__APP_CONFIG__`:

The current implementation already tries to read from runtime config. Verify it includes:

```dart
static String get geminiApiKey {
  // Try runtime config first (for production deployment)
  if (kIsWeb) {
    try {
      final windowConfig = js.context['__APP_CONFIG__'];
      if (windowConfig != null) {
        final config = windowConfig as js.JsObject;
        final geminiKey = config['GEMINI_API_KEY'];
        if (geminiKey != null && geminiKey.toString().isNotEmpty) {
          return geminiKey.toString();
        }
      }
    } catch (e) {
      print('⚠️ Error reading GEMINI_API_KEY from config: $e');
    }
  }
  
  // Try build-time environment variable
  final envVar = const String.fromEnvironment('GEMINI_API_KEY', defaultValue: '');
  if (envVar.isNotEmpty) {
    return envVar;
  }
  
  // Fall back to .env file (for development)
  return dotenv.env['GEMINI_API_KEY'] ?? '';
}
```

### Step 4: Add GEMINI_API_KEY to .env file

Add the Gemini API key to your production `.env` file:

```env
# Gemini AI API Key (for ticket analysis feature)
GEMINI_API_KEY=your_actual_gemini_api_key_here
```

### Step 5: Rebuild and Redeploy

1. **Update the docker-entrypoint.sh file** (Step 1)
2. **Update docker-compose.prod.yml** (Step 2)
3. **Rebuild the frontend Docker image:**
   ```bash
   cd apps/frontend
   docker build -t hsense/facility-erp-frontend:latest .
   docker push hsense/facility-erp-frontend:latest
   ```
4. **Update your production .env file** with GEMINI_API_KEY
5. **Redeploy:**
   ```bash
   docker-compose -f docker-compose.prod.yml pull
   docker-compose -f docker-compose.prod.yml up -d
   ```

## Troubleshooting

### Issue: "Gemini API key is not configured"

**Check:**
1. Verify `GEMINI_API_KEY` is set in `.env` file
2. Check container logs: `docker logs facility-erp-frontend-prod`
3. Verify config.js contains the key: `docker exec facility-erp-frontend-prod cat /usr/share/nginx/html/config.js`
4. Check browser console for `window.__APP_CONFIG__`

**Fix:**
- Ensure `.env` file has `GEMINI_API_KEY=your_key`
- Restart containers: `docker-compose -f docker-compose.prod.yml restart frontend`

### Issue: "All endpoints failed"

**Check:**
1. Verify API key is valid at [Google AI Studio](https://makersuite.google.com/app/apikey)
2. Check browser network tab for API calls
3. Verify API key has Generative Language API enabled
4. Check for CORS errors in browser console

**Fix:**
- Regenerate API key if needed
- Verify API key restrictions allow the API

### Issue: API calls work locally but not in production

**Check:**
1. Compare local `.env` vs production `.env`
2. Verify docker-entrypoint.sh was updated
3. Check if frontend image was rebuilt
4. Verify config.js in container has the key

**Fix:**
- Rebuild frontend image with updated docker-entrypoint.sh
- Ensure production `.env` has the key
- Restart containers

## Security Notes

⚠️ **IMPORTANT**: Since Gemini API is called directly from the browser (client-side), the API key will be visible in the browser's JavaScript code. 

**Security considerations:**
1. Consider implementing API key restrictions in Google Cloud Console
2. Restrict API key to specific domains/IPs
3. Set usage quotas/limits
4. Monitor API usage regularly
5. Consider implementing a backend proxy if you need to hide the key (not recommended for client-side usage)

## Alternative: Backend Proxy (Optional)

If you want to hide the API key, you could implement a backend proxy:

1. Store `GEMINI_API_KEY` only in backend `.env`
2. Create a backend endpoint: `POST /api/v1/ai/analyze-ticket`
3. Frontend calls backend endpoint instead of Gemini directly
4. Backend calls Gemini API and returns result

This adds complexity but hides the API key from the client.
